Software Factory — Architecture & Progress

Markdown work item in, reviewed pull request out. Sequential ticket pipeline on pi agents inside Sandcastle Docker sandboxes. State in SQLite.

MVP tickets 01–09 implemented 60/60 tests passing (incl. 2 live-agent gates) End-to-end verified: grove PR #10 As of 2026-10-27

What we're building

Drop a markdown file with front-matter into an inbox/; the factory picks it up, triages it, plans it, implements it in a sandbox, tests it, reviews it, and opens a GitHub PR whose body is a self-contained audit trail. The factory never merges.

  • Source of truth is the markdown file — claimed out of the inbox into the item store; front-matter (title, repo, base, approvals) can be edited between runs and is honored on the next run.
  • Durability is stage-level — SQLite records every item's stage/status/attempts/parking reason; a crashed stage re-runs rather than resuming half-way.
  • One seam, one port — all agent stages and their engines hide behind a single StageRunner interface; everything above it is hermetically tested with fakes.
  • Human-in-the-loop is per-item, per-stage — an approvals: list in front-matter parks the item after the chosen stages; approve/reject/answer verbs resume or route feedback.

Pipeline

Terminal & parked states

done─ terminal (PR created) rejected─ triage archives; re-drop to resurrect exhausted-rework─ 3 gate attempts, full history attached infrastructure-failure─ separate retry budget spent needs-human─ triage questions → answer awaiting-approval─ → approve human-rejected─ reason becomes feedback → resume malformed─ bad front-matter, parked with reason

Gate feedback always routes to implement (so implement → test → review re-runs in order — per ticket 06's scenario; ticket 03's "previous stage" wording is satisfied for the test gate and consciously generalized for review). Gate attempts and infra retries are independent counters; a flaky model or sandbox never burns a rework round — proven live when review's model needed 3 parse-fail retries at backoff while staying at attempt 1.

Verification

Where confidence comes from

Hermetic suite — 58 tests

Above the seam, all scenario-shaped: claim/idempotency/malformed, resume-after-crash, pass-first-time, reject-loop parking, infra flakes, budget independence, HITL park/approve/reject-with-feedback, KB append-only invariant + layer selection per stage, curator read-only proof. Real filesystem and real SQLite, fakes only for the engine.

Live-agent gates — 2 tests

Real triage verdict through Docker + Ollama Cloud, and the planted-stale-fact check: a consuming stage must verify KB facts against the repo (it reported the repo's real test runner over a planted lie). These run whenever Docker + OLLAMA_API_KEY are present.

End-to-end — grove PR #10

First real work item: 6 stages, 1 PR, 0 rework rounds, 3 infra retries (review model), ~90 min wall time including crate compilation. olsonjj/grove#10

Known environment lessons

Symlinked repo paths break Sandcastle's in-container git (fixed: realpath); sandboxed pi needs staged auth/catalog + a writable npm global prefix (fixed); pi 1.4's stream format outgrew Sandcastle 0.12's stdout tag-scanner (fixed: session-based extraction). Roadmap

Where we are, what's next

Delivered (milestones 1–5)

Skeleton → stubs → budgets → real triage → spec/implement/PR via Sandcastle → gates + rework → HITL → KB → curator. Everything observable via wb status; everything durable in SQLite.

Open / deferred (not started)

  • HITL on the first real repo — grove PR #10 ran fully autonomous; the park → approve → resume experience hasn't met a real repo yet; same for curate against grove's accumulating KB.
  • Per-stage model differentiation beyond review — mechanism exists; diversified mapping (triage/test on v4-flash) is a config edit away.
  • wb watch — loop around the tick verbs; deferred by design.
  • Web status UI — the schema already supports it.
  • Cross-repo parallelism — per-repo lock table exists; scheduler work deferred.
  • Sandbox-image maintenance — Docker build networking is currently broken under OrbStack (run-networking works); the Rust-enabled image was mutated+committed as a workaround. Revisit the toolchain install via .sandcastle/Dockerfile when builds recover.
